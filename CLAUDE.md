# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Projet

App de suivi budgétaire **100 % locale et chiffrée**, calquée sur **Budgetiz** (méthode Deux Sœurs Un Agenda) — écrans et vocabulaire repris de l'app : Budget (Variables · Fixes · Revenus · Santé), Cagnottes, Analyse, Synthèse. Expo SDK 57 + TypeScript strict + expo-router. Trois cibles : iOS, Android, et web en PWA. Interface entièrement en français ; les commits sont rédigés en français.

## Commandes

```bash
npm run typecheck                 # tsc --noEmit — à lancer après toute modification
npm test                          # vitest : calculs (plan, compte, enveloppes, semaines…) sur SQLite en mémoire
npx expo export --platform web    # build web (dist/) — vérifie aussi que le bundle passe
npx expo start                    # serveur de dev (web ou dev build natif)
npx expo prebuild                 # génère ios/ et android/ (non versionnés)
```

La vérification = typecheck + `npm test` + export (web et/ou android) sans erreur ; la CI (`deploy-web.yml`, Node 22) lance typecheck et tests avant l'export. Pas de linter.

**Tests** (`tests/`, Vitest, Node ≥ 22) : les repositories tournent sur une vraie base SQLite en mémoire (`node:sqlite`) via `tests/helpers/db.ts` (`emptyDb()` = base migrée et vidée), scénario type dans `tests/helpers/scenario.ts`. Jeu de démonstration (6 mois) pour les captures : `npx tsx --tsconfig tsconfig.json tests/helpers/demo.ts <fichier.json>` puis Réglages → « Restaurer une sauvegarde ». Les repositories et les utilitaires de calcul (`dates`, `money`) ne doivent pas importer `react-native` (sinon ils ne sont plus testables) — la palette vit dans `src/theme/palette.ts` pour cette raison. Toute modification d'une formule (plan, prévisionnel, compte) DOIT garder les tests verts, et toute nouvelle règle de calcul DOIT avoir son test (invariants : une action prévue par le plan ne change ni la fin de mois ni le début de mois déduit).

**Expo Go ne fonctionne pas** : SQLCipher est natif, il faut un development build (`expo run:android` / `run:ios`).

## Architecture

Flux de données : écrans (`app/`) → `useLiveQuery` → repositories (`src/features/*/repository.ts`) → SQLite chiffré.

- **Réactivité** : pas de cache ni de state manager pour les données. Chaque mutation dans un repository appelle `invalidateQueries()` (`src/store/invalidation.ts`, compteur Zustand) ; tous les `useLiveQuery` montés re-exécutent alors leur requête SQL. Toute nouvelle mutation DOIT appeler `invalidateQueries()`.
- **Base de données** (`src/db/`) : ouverte par `SQLiteProvider` dans `app/_layout.tsx` avec `onDatabaseInit` — qui déverrouille SQLCipher (`PRAGMA key`, première instruction obligatoire, clé 32 octets dans SecureStore) puis exécute les migrations. Migrations versionnées par `PRAGMA user_version` dans `src/db/schema.ts` : pour changer le schéma, ajouter une migration `current < 19`, ne jamais modifier `SCHEMA_V10`, les migrations V11 à V18 (dont `migrateToMonthlyEnvelopes`) ni `legacy.ts`.
- **Montants en centimes** (INTEGER) partout — colonnes `*_cents`, helpers `formatCents`/`parseAmountToCents` dans `src/utils/money.ts`. Jamais de flottants pour l'argent.
- **Périodes** : mois = `'yyyy-MM'` (`MonthKey`), semaine = date ISO de son lundi (`WeekKey`), helpers dans `src/utils/dates.ts`.
- **Écrans** (onglets `app/(tabs)/`, icônes seules + bouton **+** central qui ouvre `ajouter.tsx`) :
  - **Budget** (`index.tsx`) : mois + « Semaine n/N », **pastille du reste prévisionnel** (`ForecastPill`, verte / rouge « Dans le rouge », toucher → Synthèse), carte **Mon compte** (`AccountCard` → `compte.tsx`, **mois en cours uniquement** ; un mois à venir affiche « plan, sans ton solde actuel »), onglets segmentés (`Segmented`) **Variables** = TOUT ce qui n'est pas une facture : carte « Mes variables du mois » (reste, dépensé / prévu), **« Chaque semaine »** (cartes d'enveloppes `week` avec anneau, « Reste », « Cette semaine »), **« Montants fixes du mois »** (enveloppes `month` : Coiffure 60 €, Essence… — un montant prévu, pas une facture ; lignes avec jauge et reste), dernières dépenses (8, toutes enveloppes) ; **Factures** (`StatTrio` Total · Réglé · À débiter, charges à cocher — uniquement les `fixed_items` charges) ; **Revenus** (Total · Crédité · À créditer) ; **Santé** (Avancé · Remboursé · Reste à charge, badge « Solder » / « Terminé »).
  - **Cagnottes** (`cagnottes.tsx`, onglet à l'icône **tirelire** `MaterialCommunityIcons piggy-bank`) : carte « Total de mon épargne » (total, objectifs atteints, versements programmés du mois et % des revenus, « Nouvelle cagnotte », « Mes virements »), puis **toutes les cagnottes d'un coup d'œil**, groupées Urgence & avenir / Projets & pépins (`PotRow` : solde, jauge vers l'objectif, %, reste à mettre, date limite, versement mensuel, crayon → corriger le montant), versements du mois, puis **« Mon plan d'épargne »** (`getSavingsProjection(from, to)` : total des cagnottes fin d'année ou dans 12 mois si chaque versement programmé est fait — mois sautés exclus, versement du mois déjà fait pas recompté, plafonné à l'objectif ; chiffre + courbe `LineChart zeroBased={false}` + tableau par cagnotte), onglets Projets & pépins / Urgence & avenir, grille de cagnottes (objectif, date limite, coche du versement du mois), versements du mois.
  - **Analyse** (`analyse.tsx`, titre « Où va mon argent », `MonthSwitcher`, `Segmented` **Ce mois · Tendances · Épargne**). **Ce mois** : constats clés, 4 tuiles (dépensé par jour, possible par jour jusqu'à la fin du mois, factures et épargne en % des revenus), **« Où va mon argent »** en **diagramme de flux** (`FlowChart`, façon Sankey sur **deux colonnes** pour rester lisible sur téléphone : un nœud « Revenus » (+ « Au-delà » si dépassement) → familles factures, semaine, montants fixes, santé, épargne programmée, reste ; « Revenus » se déplie en sources comme une famille ; chaque nœud a une case d'au moins 38 px pour que son étiquette soit en face de son ruban ; au-delà de 6 postes, les plus petits sont regroupés en « Autres » dans le graphique (le tableau garde tout) ; rubans en dégradé source → destination, épaisseur ∝ montant ; toucher une famille la déplie poste par poste — chaque facture, enveloppe, frais de santé, cagnotte —, « Vue d'ensemble » pour revenir ; dévoilement animé de gauche à droite ; tableau chiffré dessous = navigation. Données `getMoneyFlowDetail` : mêmes totaux que `moneyFlowOf`, somme des postes = famille, sources + dépassement = total), **« Mes enveloppes »** (dépensé / prévu, repère de rythme), **« Semaine après semaine »** (`ColumnChart`, budget d'une semaine en repère — `getWeeklySpending`), **plus grosses dépenses** (`getTopExpenses`), rythme et semaine bouclée. **Tendances** : 6 mois empilés par famille avec les revenus en repère (`getTrend`), moyennes, mois le plus cher, tableau mois × famille. **Épargne** : économies cumulées + projection au rythme moyen, répartition des cagnottes. Calculs dans `src/features/analytics/` (rien de stocké, tout part de `getMonthSummary`). Ancien détail des constats clés : (`InsightsCard`, `src/features/insights/` — phrases générées, jamais stockées, 5 au plus, triées alerte → vigilance → bonne nouvelle → info : mois dans le rouge / plan qui tient, enveloppes dépassées ou presque vides, rythme du budget variable, dépenses vs moyenne des mois précédents, cagnotte en retard sur sa date limite ou objectif atteint, charges encore à débiter, poste principal ; mêmes chiffres que la pastille et la Synthèse), puis rythme du mois (% écoulé vs % du budget variable dépensé), semaine précédente « bouclée » → mettre de côté, épargne cumulée (courbe + projection 6 mois, `LineChart`), KPI, répartition par cagnotte (`HBars`).
  - **Synthèse** (`synthese.tsx`) : en tête **« Mon plan du mois »** (`PlanCard`) et **« Les prochains mois »** (`OutlookCard`, `getPlanOutlook` : mois en cours + 5, revenus · dépenses prévues · épargne · reste prévisionnel, **sans le solde du compte** ; toucher un mois le sélectionne), puis Revenus · Dépenses · Solde, la plus dépensée, taux d'épargne, cagnottes actives, total des avoirs, répartition des dépenses.
- **Données — axes indépendants, aucun lien croisé** (ne pas réintroduire de pont entre tables) :
  1. **Revenus & charges fixes** (`src/features/fixed/`, modale `fixe.tsx`) : `fixed_items` (`kind` income/charge, `day`, `frequency` monthly/quarterly/yearly/once, `start_month`, `end_month`, `icon`), présence d'un mois via `isDueIn`. Coche = une ligne `fixed_checks(item_id, month)`, rien d'autre. Supprimer un récurrent = l'**arrêter** à partir du mois affiché (`stopFixedItem`).
  2. **Enveloppes** (`src/features/envelopes/`, modales `depense.tsx`, `enveloppe.tsx`, `enveloppe-detail.tsx`) — toutes affichées dans **Variables** : `period` = `week` (« Chaque semaine » : Courses, Plaisir — montant par semaine, lundi → dimanche, **une semaine appartient au mois de son jeudi** (celui qui a le plus de ses jours, `monthOfWeek` ; la colonne `week` reste le lundi), budget du mois = montant × nb de semaines) ou `month` (« Montants fixes du mois » : Coiffure, Essence… — montant par mois civil ; prévu chaque mois mais **pas une facture**, reste dans Variables). `weekly_cents` porte le montant de la période. **Enveloppes propres à chaque mois** (V14) : chaque ligne d'`envelopes` appartient à UN mois (`month`), aucun lien entre les mois. **« Ma base »** (`envelope_templates`) est le modèle copié dans un mois quand on commence à le remplir (`ensureMonth`, `envelope_months_ready`) ; modifier la base ne touche pas les mois déjà ouverts. Un mois pas encore ouvert suit la base en lecture seule : `listEnvelopesForMonth` renvoie des enveloppes `virtual` (id négatif, `template_id`) — **toute action passe par `resolveEnvelopeId`** (ouvre le mois). Créer une enveloppe (`saveEnvelope` sans id) ouvre le mois d'abord. `resetMonthFromBase` remplace les enveloppes sans dépense d'un mois par la base. `expenses.week` = lundi (`weekKeyOf`, recalculé à chaque `saveExpense`). Semaine bouclée → `closeWeek` (mouvement d'épargne avec `week` + `week_closures`).
  3. **Santé** (`src/features/health/`, modale `sante.tsx`) : `health_expenses` (avancé, remboursement attendu, `settled`).
  4. **Cagnottes** (`src/features/savings/`, modales `poche.tsx`, `poche-detail.tsx`, `mouvement.tsx`) : `savings_pots` (`kind` securite/projet, `initial_cents`, `target_cents`, `monthly_cents`, `deadline`) ; solde = initial + Σ `savings_moves`. Le formulaire `poche.tsx` affiche le **« Montant actuel »** (= solde) : le corriger appelle `setPotBalance` (ajuste `initial_cents` pour que le solde tombe sur la saisie ; virements gardés, compte courant non touché) — modifiable à tout moment, aussi via « Corriger le montant » du détail. Versement programmé coché = mouvement `plan_month` (index unique). **« Pas ce mois-ci »** (V15, `savings_skips(pot_id, month)`, `setPlanSkipped`) : la cagnotte saute son versement ce mois-là (retire le versement coché du mois), `monthly_cents` reste prévu pour les autres mois ; l'épargne programmée du mois = Σ `plannedFor(pot)` (0 si sautée) — même valeur dans `getMonthSummary`, l'aperçu des mois et le compte. UI : section « Versements de <mois> » de Cagnottes et carte du détail.
- **Plan & prévisionnel** (`getMonthSummary`) : **reste à répartir** (`plan_left_cents`) = revenus − charges fixes − postes du mois (budget) − enveloppes variables (montant × semaines) − épargne programmée ; **reste prévisionnel** (`forecast_left_cents`) = reste à répartir − dépassements d'enveloppes (Σ max(0, dépensé − budget)) − santé reste à charge. Négatif = « dans le rouge » : pastille de l'onglet Budget, `PlanCard`, et aperçu en direct dans `depense.tsx` (« Cette dépense te met dans le rouge »). Garder ces trois affichages sur la même formule.
- **Mon compte** (`src/features/account/`, modale `compte.tsx`, migration V12) — un seul compte courant, sans connexion bancaire : `account` (id = 1, `start_cents`, `start_at` horodatage SQLite UTC). **Solde estimé = solde saisi + tout ce qui est noté / coché / pointé APRÈS `start_at`** : revenus crédités et charges réglées (`fixed_checks.checked_at`), dépenses **pointées** (`expenses.cleared_at`), santé avancée (`health_expenses.created_at`) et remboursée (`settled_at`), virements d'épargne (`savings_moves.created_at`). Toute nouvelle insertion dans ces tables DOIT poser `created_at = datetime('now')`. À la saisie, les revenus/charges du mois déjà passés sont cochés et les dépenses déjà débitées pointées juste avant `start_at` (pas de double compte). **Pointage** (V17) : `expenses.cleared_at` = moment où la dépense a été pointée (débitée sur le compte), NULL = « à pointer » ; une nouvelle dépense est à pointer par défaut (case « Déjà débitée » dans `depense.tsx`), coche sur chaque ligne (`ExpenseList`, `depenses.tsx` avec filtre « À pointer », `pointer=1`), `setExpenseCleared`. Le budget (enveloppes, plan, pastille) compte TOUTES les dépenses dès leur saisie ; seul le compte suit le pointage. **Fin de mois prévue** = solde estimé + revenus à créditer − charges à débiter − dépenses à pointer − reste des enveloppes (**le même « Reste » que les cartes** : Σ max(0, budget du mois − dépensé), moins les restes de semaines déjà mis de côté) − épargne programmée non versée + remboursements attendus. Contrôle affiché : **fin de mois = solde de début de mois déduit + résultat du mois (pastille) − virements d'épargne hors plan** ; ne pas faire diverger les formules du compte et de `getMonthSummary`. « Comparer avec ma banque » affiche l'écart et permet de « caler » le solde (nouvelle saisie, maintenant).
- **Clôture du mois** (`src/features/closure/`, modale `cloture.tsx`, rappel `ClosurePrompt` sur l'onglet Budget pour le mois précédent, bouton dans `enveloppes.tsx`) : pour chaque enveloppe, reste (+) ou dépassement (−) = budget − dépensé, moins les restes de semaines déjà mis de côté (imputés aux variables dans l'ordre). Actions : `save` (reste → virement vers une cagnotte), `cover` (dépassement ← retrait d'une cagnotte), `carry` (report sur l'enveloppe du même nom le mois suivant, créée à 0 € si absente). **Mécanique unique** : la clôture pose `adjust_cents −= montant` sur l'enveloppe (son budget tombe sur le dépensé) et, pour un report, `adjust_cents += montant` sur la cible ; le budget du mois d'une enveloppe = montant × semaines (ou montant) + `adjust_cents`. Rien d'autre à adapter : plan, pastille et compte restent cohérents (tests). `month_closures` garde la décision ; `undoClosureRow` la défait — appelée aussi quand on supprime le virement, l'enveloppe source ou la cible. « Terminer la clôture » = `app_meta` `closure_done:<mois>`.
- **Sauvegarde** (`src/features/backup/`) : `buildBackup` / `parseBackup` / `restoreBackup` (toutes les tables de `BACKUP_TABLES`, ordre parents → enfants ; restauration en une transaction, colonnes inconnues ignorées ; refuse les sauvegardes d'avant V14). **Toute nouvelle table de données DOIT être ajoutée à `BACKUP_TABLES`** (et au « Tout effacer » de `reglages.tsx`). Date de dernière sauvegarde dans `app_meta` (`markBackupDone` après un partage réussi) ; constat clé au-delà de 30 jours. Fichier choisi via `expo-document-picker` (`pickFile.ts`).
- **Mes dépenses** (`depenses.tsx`, lien « Tout voir · rechercher » sous les dernières dépenses) : `searchExpenses` (mois des enveloppes ou tous les mois ; chaque mot doit se retrouver dans le libellé, l'enveloppe ou le montant, sans accents ni casse).
- **Gestion des enveloppes** : `enveloppes.tsx` (« Mes enveloppes », depuis Variables, la `PlanCard` et Réglages, avec `MonthSwitcher`) liste les enveloppes **du mois sélectionné**, « Repartir de ma base », puis **Ma base** ; la modale `enveloppe.tsx` édite une enveloppe d'un mois ou, avec `base=1`, une ligne de la base ; `depense.tsx` propose les enveloppes du mois de la date (variables : mois de la semaine ; postes : mois civil) et garde l'enveloppe du même nom si la date change de mois ; une carte d'enveloppe à 0 € ouvre directement sa modification ; le détail porte un bouton « Modifier le montant ».
- **Agrégats** (`src/features/summary/`) : `getMonthSummary` lit les axes, ne stocke rien. **Dépenses du mois = charges fixes (prévues) + Variables dépensé + postes dépensé + santé reste à charge** ; **Solde = revenus − dépenses** = « économies du mois » (c'est aussi l'épargne de l'Analyse, cumulée par `getBalanceHistory`). Couleurs des 4 familles (`SPENDING_GROUPS`) = 4 premières teintes de `categoryPalette`, dans l'ordre (validées).
- **Migrations** : installation neuve → `SCHEMA_V10` (`seedDefaults`) puis `MIGRATION_V11` (période d'enveloppe, icône de charge, date limite, santé) `MIGRATION_V12` (compte, horodatages), `MIGRATION_V13` (bornes / montants par mois, remplacé ensuite) et V14 `migrateToMonthlyEnvelopes` (enveloppes propres à chaque mois + base ; conversion : la base reprend les récurrentes actives, chaque mois avec dépenses, montant propre ou ponctuelle — et le mois courant — reçoit sa copie avec son montant, les dépenses y sont rattachées), puis `MIGRATION_V15` (`savings_skips`, « Pas ce mois-ci ») `MIGRATION_V16` (`app_meta`, `envelopes.adjust_cents`, `month_closures`) `MIGRATION_V17` (`expenses.cleared_at`, dépenses existantes pointées à leur `created_at`) et V18 `upgradeLegacyColors` (ancienne palette brune → palette pastel, même rang ; aussi appelée après les données d'exemple de « Tout effacer »). Base existante (V1–V9) → chaîne héritée `src/db/legacy.ts` (figée) puis `CONVERT_V9` en une transaction : budgets → 2 enveloppes (Courses = « Alimentation », Autres = le reste, × 12/52), dépenses libres → dépenses, revenus → revenus ponctuels, factures → charges mensuelles + coches, comptes → poches, virements effectués → mouvements.
- **Web/PWA** : SQLCipher, SecureStore, Face ID et `Alert` n'existent pas sur web. Les gardes `Platform.OS === 'web'` sont dans `src/db/index.ts`, `BiometricGate`, `exporter.ts` et `reglages.tsx`. Utiliser `notify`/`confirmAction` (`src/utils/dialogs.ts`) au lieu de `Alert.alert` (muet sur web). Sur web, la persistance passe par OPFS (wasm) — `metro.config.js` déclare `.wasm` comme asset, ne pas le retirer.
- **Mois global** : `useSelectedMonth` (`src/store/month.ts`) pilote tous les onglets. Ne pas recréer de state local de mois dans un écran ; les modales prennent `params.month`.
- **Affichage « reste d'abord »** : pour une enveloppe, « Reste : X » (rouge « Dépassé » si négatif) sous « dépensé / budget ».
- **Icônes** : toutes dérivées de `assets/icon-source.webp` (illustration d'origine, plaque rose à coins arrondis sur fond blanc). Règles suivies pour les regénérer : recadrer sur la plaque, **icône pleine** (`assets/icon.png` 1024, `public/icons/icon.png` 512) sans coin blanc — iOS/Android posent leur propre masque ; `splash-icon.png` garde ses coins arrondis en transparence (il flotte sur le fond crème) ; Android adaptatif = avant-plan dans la zone sûre (~66 %) + fond rose plein (`#F8D8D8`, aussi dans `adaptiveIcon.backgroundColor`) ; PWA : une icône `maskable` en plus de `any` dans `public/manifest.json`. Changer une icône ⇒ incrémenter `CACHE_NAME` dans `public/sw.js`, sinon les appareils gardent l'ancienne en cache.
- **Navigation** : onglets dans `app/(tabs)/`, formulaires en modales à la racine de `app/` (déclarées dans `app/_layout.tsx`). `app/+html.tsx` porte les balises PWA (manifest, service worker) avec des chemins **relatifs** — requis pour GitHub Pages sous sous-chemin.
- **Design pastel** (plus de brun ni de terracotta — demandé par l'utilisatrice) : fond lilas très clair (`#F6F5FB`), cartes blanches **sans bord en clair** avec ombre lavande légère et grands rayons, **lavande** (`primary` `#6E62D0`, blanc dessus 4,9:1) pour l'action, **menthe** (`secondary`, coches faites), **indigo** (`navy`, « à venir »), **rose poudré** (`rose`, « Réglé / Crédité »), miel (`gold`). Pastilles d'icône = **fond teinté doux + icône colorée** (`CategoryIcon`, `StatTrio`, `CheckRow`), jamais de rond plein avec icône blanche ; boutons en pilule (secondaire = `primarySoft` + texte lavande) ; segment actif = `primarySoft` ; bouton + en dégradé lavande → pivoine (`expo-linear-gradient`). Thème sombre nuit indigo (`#16161F` / cartes `#222230`). En-tête d'onglet = `AppHeader` (menu → réglages, titre centré), mois = `MonthSwitcher` (flèches, sous-titre « Semaine n/N »). Listes = `CheckRow` (pastille, libellé + « Le 6 du mois », montant signé, coche ronde).
- **Typographie** : deux polices Google chargées au runtime par `useFonts` dans `app/_layout.tsx` (paquets `@expo-google-fonts/schibsted-grotesk` et `instrument-sans` ; **pas** le plugin `expo-font` dans app.json — il casse l'export web). **Schibsted Grotesk** = titres + montants (chiffres tabulaires, la signature), **Instrument Sans** = corps. Jetons dans `src/theme` (`fonts.*`). **Toujours** passer par les composants de `src/components/ui/Text.tsx` (`Title`, `Heading`, `Eyebrow`, `Body`, `Caption`, `Money`) plutôt que `<Text>` brut : sur natif, `fontWeight` est ignoré pour les polices custom, il faut la bonne famille. `Money` prend `cents` + `signed` et formate lui-même. Sur-titres de section (`SectionHeader`) et libellés de formulaire = capitales espacées (eyebrow).
- **Design des données** : `categoryPalette` (`src/theme/palette.ts`, 11 pastels) est **validée** avec `scripts/validate_palette.js` du skill dataviz dans les deux modes (bande de luminosité, chroma, ΔE daltonisme adjacent ≥ 9,1, vision normale ≥ 15,9) — ne pas réordonner ni ajouter de teinte sans revalider. En clair, 8 teintes sont sous 3:1 sur blanc : une donnée colorée a toujours son libellé / sa valeur à côté (légendes-tableaux, détail au toucher). **Couleur stockée = teinte claire ; à l'affichage passer par `theme.tint(hex)`** (pas sombre `categoryPaletteDark` en mode sombre, couleur inchangée hors palette) — déjà fait dans `CategoryIcon`, `ProgressBar`, `ProgressRing`, `HBars`, `StackedBar`, `ColumnChart`, `Chip`, `AppearancePicker`. Graphiques (`src/components/charts/`) : un seul axe, segments séparés de 2 px, haut arrondi, filets de grille discrets, chiffres en encre, légende dès deux séries, détail chiffré au toucher (jamais la couleur seule). Les chiffres/labels restent en encre ou muted, jamais en couleur de série (la pastille/barre porte l'identité). Couleur par défaut d'une nouvelle enveloppe/poche : la teinte suivante de la palette (ordre fixe).
- **Thème** : `useTheme()` (`src/theme/`) combine le schéma système et la préférence utilisateur `useThemePref` (`src/store/themePref.ts`, Auto/Clair/Sombre, persistée SecureStore natif / localStorage web, hydratée au lancement dans `app/_layout.tsx`, réglable dans Réglages → Apparence) ; les couleurs viennent toujours du thème ou de la couleur d'enveloppe/poche en base, jamais en dur dans les écrans. Texte posé sur une surface encre (boutons, pastilles pleines) = `theme.colors.onAccent` / `onAccentMuted`.
- **Couleurs d'enveloppes/poches** : `categoryPalette` (`src/theme`) — 11 pastels (lavande, sauge, violette, menthe, miel, framboise, pousse, lagon, corail, bleuet, pivoine), proposés par `AppearancePicker` (`src/components/ui/`).
- **Interface premium** : le contenu des écrans est centré dans une colonne max 560 px (`Screen`) — mobile first, élégant sur tablette/desktop ; la barre d'onglets est en position absolue : les écrans d'onglet passent `bottomInset={90}` à `Screen`. Les composants interactifs (Card, Button, Chip, FAB) ont des états hover (web) via le state Pressable (`hovered`, casté) et des `accessibilityRole/Label`. Chargement = `Skeleton` (pulsation 900 ms), jamais de spinner nu ; la jauge s'anime en 250 ms.
- **Jauges** (`ProgressBar`) : compteur horizontal arrondi ; dépassement → remplissage rouge. Prop optionnelle `markerRatio` = fin trait repère de « rythme » ; pour l'enveloppe de la semaine en cours on passe `weekPaceRatio(week)` (fraction de la semaine écoulée). Couleur : celle de l'enveloppe sous ~90 %, ambre proche, rouge au-delà.
- **Aperçu web** : `.claude/launch.json` déclare le serveur `web` (`npx expo start --web`) pour l'outil de preview ; utile pour vérifier le rendu (l'app native n'est pas visualisable ici).

`.github/workflows/deploy-web.yml` publie la PWA sur GitHub Pages à chaque push (injecte `experiments.baseUrl = /<repo>` dans app.json avant l'export ; `dist/404.html` = copie d'index.html pour le routage SPA).
